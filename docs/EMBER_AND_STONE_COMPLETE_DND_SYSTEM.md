# Ember & Stone — Complete D&D Learning and Play System

## Mission

Ember & Stone is a complete start-to-finish Dungeons & Dragons learning, reference, practice, play, and game-running ecosystem.

The goal is not to make another rules wiki, character builder, adventure site, VTT, or DM toolbox.

The goal is to make the clearest place to learn and use D&D from:

> “What is a d20?”

through:

> “I can build, play, optimize, DM, design encounters, run campaigns, adjudicate high-level magic, and understand why the rules work.”

Everything public-facing is free. Revenue comes from the Ember & Stone YouTube channel, voluntary donations such as Buy Me a Coffee, and appropriate future sponsorship/affiliate opportunities—not from locking core learning behind a paywall.

## Product philosophy

### Simple first. Depth on demand.

Every concept should support three depths:

1. **Quick answer** — plain-language explanation.
2. **Learn more** — rules, examples, and common mistakes.
3. **Deep dive** — optimization, edge cases, advanced interactions, edition differences, tactics, and DM adjudication.

A beginner should never be overwhelmed by expert detail.

An expert should never be blocked by beginner hand-holding.

### One ecosystem, not a pile of tools

Users should see Ember & Stone, not a collection of unrelated repositories.

Specialist repositories may continue to provide engines and data behind the scenes, but the public experience should feel unified.

### Learn by doing

Every important rule should eventually support some combination of:

- written explanation;
- matching Ember & Stone video;
- interactive example;
- Iron Pit laboratory;
- Hearthford adventure example;
- character-sheet example;
- monster example;
- DM adjudication example;
- practice exercise.

### Never make users hunt for context

If a rule, spell, condition, feature, monster ability, or derived number appears on screen, the user should be able to inspect it there.

Do not require unnecessary tab changes or compendium searches.

# Question-to-answer contract

If a user has a practical D&D question, Ember & Stone should aim to answer it.

Examples:

- How does AC work?
- How do saving throws work?
- What does restrained do?
- What happens at 0 HP?
- Can I cast two spells in one turn?
- How does concentration work?
- How do I build a Rogue?
- Which ability score matters for Paladin?
- How do I run a dragon?
- How do I build a trap?
- How do I make a mystery?
- How do I DM my first session?
- How do I challenge a level-17 party?
- How should a monster use flight?
- What is the difference between 2014 and 2024 rules?

Each answer page should connect to:
- concise written answer;
- full lesson;
- video;
- practice/lab;
- relevant character or monster examples;
- relevant Hearthford scene when available;
- related topics.

# Data principle

The long-term system should use shared concept IDs so the same concept connects all surfaces.

Example:

```
combat.saving-throws.dexterity
```

may link:
- lesson;
- video;
- Iron Pit lab;
- character fields;
- spell examples;
- monster examples;
- Hearthford adventure scene;
- DM lesson.

This prevents duplicate contradictory explanations.

# Success definition

A person should be able to arrive knowing nothing about D&D and remain inside Ember & Stone through years of increasing mastery.

The ecosystem succeeds when the same site can help:

- a person learning what a d20 is;
- a player making their first character;
- a group running its first combat;
- a DM running their first session;
- an optimizer comparing builds;
- an experienced DM designing a complex mystery;
- a veteran testing high-level RAW interactions in Iron Pit;
- an expert running level-20 play.

That is the product boundary:

**Start to finish. Everything needed to learn, play, understand, build, and run D&D clearly.**
